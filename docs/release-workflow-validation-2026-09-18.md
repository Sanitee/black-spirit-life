## Review corrections and limits

Independent component review caught and fixed broad generated-path exclusion,
incomplete selected SDK coverage, dependency roots hidden inside excluded
outputs, and exact OCR-generated bin/obj handling. Tests now ensure unrelated
assets/bin remains a source input. Whole selected installation roots and actual
resolved package roots must be covered for optional bundle reuse.

A final independent read-only integration review found two further issues,
both corrected: same-source builds with different plan output names now share
one source-scoped OS lock; damaged workflow status cannot claim a passed gate
with empty proof, mismatched origin/exit status, or an earlier unmet gate.
The added negative cases bring checkpoint assertions to45 and workflow
assertions to91. Final combined evidence is recorded at the top;
the earlier combined manifests remain retained historical evidence.

Actual trusted builder branches are exercised with explicit external compiler,
packager and privacy/helper mocks: forced package failure retains a verified
checkpoint, retry skips only compilation/reset, fresh staging is independent,
and all validation boundaries run again. A static FileVersionInfo read is
explicitly substituted in that fixture; the real conditional identity gate is
retained and negative-tested. These fixtures are not a compiled-app retry test.

The workflow uses complete suite discovery and machine reports, exact source
and helper context, durable attempt records, explicit external review gates,
and dedicated candidate/lifecycle/installed-report validators. Prepare/build
cannot mean release complete. Source does not change during artifact sealing.
